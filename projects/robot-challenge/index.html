Autonomous Object-Collecting Robot

SNU AI Robot Challenge · Team 7 · 2026 · 2nd Place

An autonomous robot that detects, collects, and delivers objects within a three-minute match.

CodeFinal run 1Final run 2Official coverage

Task and design constraints

The target object classes are announced at match time. The robot must identify them, collect them, and return them to the delivery zone.

  • Perception: Recognize targets from two angled cameras while the robot moves.
  • Mechanism: Plan around a passive basket that holds three objects and can release them during reverse motion.

My contribution

I contributed across perception and model training, planning, data collection, hardware, and system integration. The robot and competition result were developed with Team 7.

Robot system

1. Hardware and motor interface

A Jetson Orin Nano runs perception and navigation. An ESP32 drives the four mecanum-wheel motors.

  • Velocity commands: Send body-frame motion commands over USB serial and convert them into wheel motion.
  • Calibration: Calibrate wheel direction and feed-forward gains. Include a duration and auto-stop in motion commands.

2. Dual-camera perception

Run YOLO instance segmentation on both cameras and combine the detections for navigation.

  • Shared bearings: Use camera intrinsics and toe angles to express detections in a common forward-facing view.
  • Target filtering: Combine confidence, range-normalized mask area, bearing, and arena-cell ownership.
  • Navigation input: Send the merged detections through a UDP interface.

normalized area = mask area × (range / reference range)²

3. Collection and delivery planning

Follow a fixed sweep route and use live detections to trigger object collection.

  • Collection: Approach a selected target with forward motion to load the passive basket.
  • Delivery: Interrupt the sweep when the basket is full and return to the delivery zone.
  • Loaded motion: Account for object retention during alignment, braking, and return maneuvers.

4. Localization and motion control

Fit arena walls in LiDAR scans to estimate pose. Use integrated IMU yaw to stop calibrated turn pulses.

  • Lateral motion: Use LiDAR feedback for strafing after the timed alternative proved unreliable during calibration.
  • Braking: Apply calibrated reverse pulses and keep cruise speed within the measured braking range.

5. On-device and field validation

Tune perception and motion together on the competition hardware.

  • Inference latency: Benchmark models on the Jetson and set detection gates for the available observation window.
  • Camera reliability: Check frozen streams and compare raw frames with motion logs during tuning.
